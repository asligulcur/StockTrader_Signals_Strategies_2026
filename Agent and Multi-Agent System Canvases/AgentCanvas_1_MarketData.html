StockTrader
StockTrader — Agent 1 of 4: Market Data Component (non-LLM deterministic data retrieval and indicator computation)
1 System Intent
1
🎯 Use Case / Purpose
Fetch real historical stock data from yfinance and compute all technical indicators required by both downstream strategy agents. This component is the system's single source of truth — it ensures both strategies reason over identical, deterministic, verifiable data with zero LLM involvement.
2
✂️ Task Slice / Goal
Given a stock ticker (e.g., "NVDA"), retrieve 120 calendar days of OHLCV data, compute derived indicators including 20d/50d MAs, 14-day RSI, 30d and 90d volatility (σ of daily returns), 14-day ATR and ATR % of price, worst single-day drop (90d), 52-week distances, drawdowns, volume trends, daily return statistics — return a structured Python dict (native JSON-serializable types).
3
👥 Users / Stakeholders
Consumer A Momentum Trader agent — consumes moving averages, volume trend, positive/negative day ratios
Consumer B Value Contrarian agent — consumes 52-week distances, RSI, drawdown metrics
Consumer C Evaluator agent — consumes market data summary for contextualizing strategy comparison
Downstream JSON output file — market_data_summary section enables human verification of agent reasoning
2 Bounded Behavior
4
⇄ Inputs / Outputs
IN Stock ticker string (e.g., "NVDA") from config.py ticker list
OUT Python dict: current_price, MAs, RSI, volatility_30d / volatility_90d, atr_14, atr_pct_of_price, max_single_day_drop_90d, 52-week distances, drawdowns, volume trend, daily return stats — numpy types → native Python
5
🔧 Tools / Permissions
ALLOW yfinance API (read-only: historical OHLCV, dividends, 52-week data), Python standard library math operations
DENY Any LLM API, any write operation, any network call beyond yfinance, filesystem access, any other external API
6
🛡️ Autonomy / Human Checkpoints
Autonomous Full data fetch, all indicator computations, type conversions, rounding — entirely autonomous and deterministic
Gated None during execution — all outputs are verifiable post-hoc by comparing computed values against raw yfinance data
7
📜 Operating Rules / Policies
HARD Never make an LLM call. Never fabricate or interpolate missing data points. Raise ValueError on insufficient data (< 90 trading days).
SOFT Round all floats to 4 decimal places. Convert all numpy types to native Python. Compute RSI manually (no external indicator library).
ORG Compute all indicators required by both chosen strategies — do not compute indicators for unchosen strategies.
Bounded Agentic System
3 Context & Evaluation
8
💾 Memory / Context
Session Raw OHLCV DataFrame from yfinance, computed indicator dictionary — both discarded after return
Persist None — stateless function. Each ticker starts fresh. No caching of prior fetches.
Limit ~120 days × 6 columns = ~720 data points per ticker. Negligible memory footprint.
Privacy No PII involved — all data is publicly available market data from yfinance.
9
⚠️ Failure Conditions / Escalations
No data yfinance returns empty DataFrame → raise ValueError("Insufficient data for {ticker}"), skip stock
Partial data < 90 trading days available → raise ValueError, do not compute partial indicators
API down yfinance network failure → exception propagates to orchestrator, stock is skipped with console warning
Bad ticker Invalid ticker symbol → yfinance returns empty data → caught by "No data" handler above
10
✅ Success Criteria
Completeness All ~25 indicator fields populated — no None or NaN values in the returned dictionary
Accuracy RSI, moving averages, and volatility match manual calculation from raw OHLCV data within rounding tolerance
Serializable json.dumps(output) succeeds without errors — all numpy types converted to native Python
Timeliness Completes in < 5 seconds per ticker (yfinance fetch + computation)
Determinism Same ticker on same day produces identical output on every run — zero non-determinism
