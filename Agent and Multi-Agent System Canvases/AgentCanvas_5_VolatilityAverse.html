Agent System Specification Canvas

StockTrader
StockTrader — Volatility Averse (strategy_c). Runs in parallel with Momentum and Value Contrarian on the same market data dict; uses a dedicated user prompt that foregrounds ATR, σ(returns), and tail risk.
THIRD STRATEGY
1 System Intent
1
🎯 Use Case / Purpose
Analyze the same stock data through a path-risk lens — “survive first, profit second; avoid turbulence.” This agent cares whether the ride is orderly (low realized volatility, contained ATR, shallow worst-day drops), not whether the crowd is greedy or fearful. It is the third strategy in the system, running alongside Momentum and Value Contrarian and adding three-way agreement patterns (unanimous, 2–1, or three distinct decisions) to the evaluator’s synthesis.
2
✂️ Task Slice / Goal
Receive the volatility-focused user prompt (same underlying dict as other strategies). Output JSON: BUY/HOLD/SELL, confidence 1–10, 3–5 sentence justification citing ≥3 specific numbers, prioritizing volatility_30d, volatility_90d, atr_14 / atr_pct_of_price, max_single_day_drop_90d, and drawdown — not MA trend or 52-week “story” as primary drivers.
3
👥 Users / Stakeholders
Consumer Evaluator — receives strategy_c alongside strategy_a and strategy_b for three-way synthesis
Peers Momentum & Value Contrarian — same inputs, never see this agent’s output
Reviewer Analyst — reviews three_way_pattern in the JSON outputs
2 Bounded Behavior
4
⇄ Inputs / Outputs
IN System prompt from prompts/strategy_c.txt + format_volatility_averse_user_prompt() (volatility metrics first; MAs/52w as secondary context only)
OUT JSON: {"name": "Volatility Averse", "decision", "confidence", "justification"} → merged as strategy_c in outputs/{TICKER}.json
5
🔧 Tools / Permissions
ALLOW Anthropic Messages API — one inference call (claude-sonnet-4-6, temperature 0.3)
DENY yfinance, other agents’ outputs, tools, web search
6
🛡️ Autonomy / Human Checkpoints
Autonomous Single-shot recommendation from structured data; no human in the loop
Gated Post-hoc: verify citations use vol/ATR/drop fields, not only RSI
7
📜 Operating Rules / Policies
HARD ≥3 numeric cites from vol path metrics. JSON only. No access to strategy_a/b.
SOFT Bias toward HOLD when σ and ATR sit in a middle band; SELL when turbulence is extreme; BUY when tape is calm and contained
Persona Risk-averse, process-first; allergic to whipsaws
Bounded Agentic System
3 Context & Evaluation
8
💾 Memory / Context
Session System + one user message; single-turn
Persist None — stateless per ticker
Limit Similar token budget to other strategy agents (~1.5k in / ~400 out)
9
⚠️ Failure Conditions
Bad JSON Same retry + parse fallback as strategy_a/b
Leak Agent argues only from 52-week distance without σ/ATR → prompt compliance issue
10
✅ Success Criteria
Schema Valid JSON with name, decision, confidence, justification
Ground Justification anchored in volatility_30d, volatility_90d, atr_14 or atr_pct_of_price, max_single_day_drop_90d (≥3)
Extension Enables non-redundant three-way splits (e.g. NVDA BUY/HOLD/SELL)
