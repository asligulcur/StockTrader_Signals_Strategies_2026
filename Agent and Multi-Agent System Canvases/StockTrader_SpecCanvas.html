Multi-Agent System Specification Canvas

94815 · Agentic Technologies · L6
StockTrader — Two competing LLM-powered strategy agents (Momentum Trader & Value Contrarian) independently analyze real stock data via yfinance, produce BUY / HOLD / SELL recommendations, and an Evaluator agent synthesizes agreement or disagreement.
1 System Intent
1
🎯 System Mission
Given a stock ticker, fetch real market data and produce independent investment recommendations from opposed philosophies — then explain agreement and disagreement. The required core is two behaviorally distinct strategies (trend-following vs. mean-reversion) plus a neutral evaluator. The implementation adds a bonus third strategy — Volatility Averse (path risk / ATR / σ) — running in parallel on the same data, so the evaluator performs three-way synthesis (unanimous, 2–1, or three distinct). The end user is the student-analyst reviewing JSON and the comparative report.
2
👥 Agent Roster & Profiles
Agents Market Data Component (non-LLM) — yfinance + indicators (incl. ATR, 30d/90d σ). Momentum Trader — trend-following. Value Contrarian — mean-reversion. Volatility Averse (bonus) — turbulence / path risk. Evaluator — compares three recommendations and explains three-way patterns; also records Momentum–Contrarian agreement.
Profiling System prompts: strategy_a.txt, strategy_b.txt, strategy_c.txt (bonus), evaluator.txt. Each encodes decision framework, data priorities, and ignore lists.
Justify Strategy agents must be separate — no agent sees another's output before producing its own (orchestrator-enforced). The Evaluator is separate for neutrality. Market Data is non-LLM for reproducibility.
3
🔲 System Scope & Boundaries
In scope Fetch 90+ days of historical price data for 6 stocks (NVDA, TSLA, JNJ, INTC, GME, JPM). Compute technical indicators (MAs, RSI, volatility, drawdown). Generate independent BUY/HOLD/SELL recommendations with confidence scores (1–10) and data-grounded justifications (3–5 sentences). Compare recommendations and produce evaluator analysis. Save structured JSON outputs per stock plus a cross-stock summary.
Why MA The assignment's intellectual core — structured disagreement from identical data — requires at minimum two agents with incompatible philosophies plus a neutral arbiter. A single agent prompted to "consider both perspectives" would hedge and blend rather than commit to opposing positions. Separation enforces genuine behavioral independence.
Out scope No live trading, no portfolio optimization, no backtesting engine, no real-time data streaming, no financial advice. The system does not predict whether a stock will actually go up or down. Grading is based on behavioral clarity and analytical depth, not financial accuracy.
2 Multi-Agent Structure
4
🏗️ Social & Organizational Structure
Hierarchy Flat pipeline with orchestrator (orchestration.py). Market Data feeds three strategy agents; all three feed the Evaluator. No agent manages another.
Teams Three parallel branches (implementation): Momentum, Value Contrarian, and Volatility Averse — independent analysts on the same input — parallel execution, no collaboration. Evaluator downstream synthesizes all three.
Authority No agent can override or modify another agent's output. The Evaluator reads both outputs as immutable evidence and produces its own analysis. The orchestrator controls execution order but has no authority over content. All outputs are append-only.
Trust Market Data is trusted (deterministic yfinance pipeline). Strategy agents are isolated. Evaluator treats strategy outputs as given inputs.
5
📡 Communication Structure & Protocol
Topology Hub-and-spoke. Orchestrator routes Market Data → three Strategy agents → Evaluator. No agent-to-agent messaging.
Messages Market Data → each strategy: same dict (Volatility Averse uses a volatility-emphasized user prompt). Strategies → Evaluator: three JSON blobs. All structured.
Pattern Single-pass pipeline — fetch → analyze (×3 parallel) → evaluate → save.
6
🌐 Environment & Interface Structure
Type Virtual environment: yfinance API (read-only financial data) + Anthropic Messages API (inference). No physical environment, no sandbox simulation, no database.
Shared The market data dictionary is shared identically across all three strategy agents. outputs/ persists JSON.
Boundary External access is limited to two APIs: yfinance (data in) and Anthropic (inference). No web browsing, no file system writes outside outputs/, no network calls beyond these two endpoints. The system is read-only with respect to the external world — it produces recommendations but takes no action.

3 Multi-Agent Behavior & Control
7
🧩 Individual Behavior Specification
Spatial Market Data: yfinance only. Each strategy agent: one Anthropic call, same data dict, different system prompt. Evaluator: one Anthropic call with three strategy outputs + market summary.
Temporal Per stock: Market Data → three strategies concurrently (asyncio.gather) → Evaluator. Stocks sequential with 2s delay.
Cognitive Market Data: deterministic rule-based computation (no reasoning). Strategy agents: single-shot prompted reasoning — each receives data + system prompt and produces a structured JSON response in one LLM call. No chain-of-thought, no tool use, no ReAct loops. Evaluator: same single-shot pattern, but with a comparative synthesis prompt.
8
🔄 Collective & Social Behavior
Planned Parallel analysis by three strategies (implementation), then neutral three-way synthesis. No dialogue between strategies.
Emergent Possible convergence drift: if prompts are insufficiently differentiated, both agents may produce similar hedged outputs despite different instructions. Possible justification-data disconnect: agents may generate plausible-sounding reasoning that doesn't actually reference the specific numbers provided. These are the primary failure modes to monitor in outputs.
Social Competitive framing: multiple philosophies on identical data. Evaluator synthesizes without choosing a winner.
9
📜 Operating Rules, Norms & Human Checkpoints
Norms All agent justifications must reference ≥3 specific data points from the market data. Decisions must be exactly one of BUY, HOLD, or SELL. Confidence must be an integer 1–10. Justifications must be 3–5 sentences. The Evaluator must never simply restate decisions — it must explain the behavioral logic behind divergence.
Rules LLM calls use temperature 0.3 for consistency. Maximum 3 retries per LLM call with 1-second backoff. 3-layer JSON parsing fallback (raw → code-block extraction → brace extraction). 2-second delay between stock analyses. All numpy types converted to native Python before JSON serialization.
Termination The system terminates after all 6 stocks are processed and summary.json is written. No iterative convergence — each stock is a single pass. If all retries fail for an LLM call, the system records an ERROR decision and continues to the next stock rather than halting.
Gated No real-time human checkpoints during execution. Human review occurs post-run: the student inspects JSON outputs, verifies justifications reference real data, and identifies weak results for the required "failure or surprise" documentation in the report.
Denied No agent may execute trades, access external APIs beyond yfinance and Anthropic, write files outside outputs/, modify another agent's completed output, or make more than one LLM call per invocation. The Market Data Component may never make LLM calls.
10
♻️ Cross-Domain Feedback Topology
Reinforcing None by design within a single run. The single-pass architecture prevents reinforcing loops — no agent output feeds back into any agent's input. However, across iterations (if the student re-runs with tuned prompts), a reinforcing loop exists: observed convergence → prompt differentiation → greater divergence → richer analysis → further prompt refinement.
Balancing The Evaluator acts as the system's balancing mechanism. When strategy agents produce extreme or poorly justified recommendations, the Evaluator's analysis exposes weak reasoning — which signals the designer to adjust prompts. This is a human-in-the-loop balancing loop that operates between runs, not within a run.
Dominance In the current single-pass design, no feedback loop dominates because none operate intra-run. If the optional Debate Mode extension were implemented (agents respond to each other's reasoning in a second round), a reinforcing convergence loop would emerge where agents moderate toward each other, potentially collapsing designed disagreement.
Cross-domain Market Data (quantitative domain) → Strategy agents (behavioral/interpretive domain) → Evaluator (meta-analytical domain). The critical cross-domain handoff is the formatting of numerical indicators into natural-language user prompts — this translation layer determines how much quantitative signal survives into the LLM's reasoning. Poorly formatted data leads to generic justifications regardless of prompt quality.
4 Context & Evaluation
11
💾 System I/O & Shared State
IN List of stock tickers (configured in config.py: NVDA, TSLA, JNJ, INTC, GME, JPM). ANTHROPIC_API_KEY environment variable. No user interaction at runtime — the system is fully batch-driven.
OUT Per-stock JSON: market_data_summary, strategy_a/b/c, evaluator (agents_agree, agents_all_agree, analysis), three_way_pattern. summary.json includes total_agreements_ab, total_all_three_agree, etc.
Shared Market data dict computed once, passed identically to all three strategy agents. outputs/ written by orchestrator only.
Private Each strategy agent's system prompt is private to that agent — the other strategy never sees it. Each agent's LLM reasoning trace (internal to the Anthropic API call) is ephemeral and not stored. The Evaluator sees strategy outputs but not their system prompts.
12
⚠️ System Failure Modes & Escalation
Cascade If Market Data returns incorrect indicators (e.g., wrong RSI calculation), both strategy agents reason on corrupted data and the Evaluator synthesizes corrupted outputs — a full-chain cascade. If one strategy agent hallucinates a data point not in its input, the Evaluator may incorporate the hallucination into its analysis.
Deadlock Minimal risk due to single-pass architecture. The only potential stall is Anthropic API timeout or rate limiting. Mitigated by 3 retries with backoff and a fallback ERROR dict that allows the pipeline to continue past a failed LLM call.
Herd Primary herd risk: both agents converge to identical HOLD recommendations with generic reasoning, collapsing designed disagreement. This is the most likely failure mode and manifests when prompts are insufficiently differentiated or when a stock's data has no extreme signals. Secondary: the Evaluator may validate weak strategy reasoning rather than critiquing it.
Escalate No automated escalation. All escalation is post-hoc human review: the student examines JSON outputs for generic justifications, data-free reasoning, universal agreement, or internally inconsistent recommendations. Weak results are documented in the required "failure or surprise" section of the report.
13
🎲 Scenario & Uncertainty Management
Uncertainty Data uncertainty: yfinance data may have gaps, splits, or delayed updates. Model uncertainty: LLM reasoning is non-deterministic even at low temperature; the same data may produce different recommendations on re-run. Parameter uncertainty: indicator thresholds (RSI overbought at 70 vs. 75, drawdown significance at 20% vs. 30%) are hardcoded in prompts and may not suit all market regimes.
Scenarios Six stocks are deliberately chosen to represent distinct market scenarios: strong uptrend (NVDA), high volatility (TSLA), stable/sideways (JNJ), significant decline (INTC), meme/retail volatility (GME), and large bank / rate–credit cycle (JPM). This selection is designed to surface at least one agreement and one sharp disagreement. The student selects scenarios; the system does not generate them.
Communication Uncertainty is communicated via confidence scores (1–10) from each strategy agent, the Evaluator's narrative analysis of divergence, and the explicit agents_agree boolean. The system does not produce probability distributions or confidence intervals — uncertainty is surfaced qualitatively through the comparison of opposing perspectives.
Purpose Explore. Explores how multiple behavioral frameworks (including optional third) interpret the same evidence; value is in comparison, not forecasting.
14
✅ System Success Criteria
Individual Each strategy agent produces a valid JSON with a clear BUY/HOLD/SELL decision, confidence 1–10, and a 3–5 sentence justification that references ≥3 specific data points from the market data. The Evaluator produces an analysis that identifies the behavioral logic behind agreement or disagreement, not mere restatement of decisions.
Collective The multi-agent system produces meaningfully different recommendations across the stock set — at least one agreement and at least one disagreement. The two strategies' outputs must be distinguishable in reasoning style and data emphasis, not just in the final decision label. A single agent prompted to "consider both perspectives" could not produce the same structured independence.
Emergent Monitor for convergence collapse (both agents always agree), justification drift (reasoning disconnects from provided data), and personality leakage (Momentum Trader citing contrarian logic or vice versa). Any of these indicate prompt design failure and should be documented as the required "failure or surprise" case.
Safety No financial actions taken. No data written outside outputs/. No PII processed. All API keys loaded from environment variables, never hardcoded. Outputs are clearly labeled as analytical exercises, not investment advice. The system gracefully degrades on LLM failure (ERROR fallback) rather than crashing.
